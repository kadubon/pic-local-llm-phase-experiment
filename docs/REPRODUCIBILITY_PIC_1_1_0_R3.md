# Reproduce or reanalyze PIC 1.1.0 R3

Use a fresh checkout/result directory. R3 never overwrites an existing panel,
warmup or preregistration. Earlier experiment bytes remain protected. The exact
PIC wheel, installed model digest, protocol, source trust manifest and limits
are in [PROTOCOL_PIC_1_1_0_R3.md](PROTOCOL_PIC_1_1_0_R3.md).
No automatic model download, cloud inference, external search or publication.

## Existing isolated environment

The recorded run reuses `.venv-pic110` without installations or updates.
For an independently prepared environment, use Python 3.14 and the hash lock
`configs/requirements.pic110.lock`, with PIC non-editable 1.1.0 and only this
experiment package editable. Verify the official wheel digest and installed
payload against the wheel. Only an already available `gemma4:e4b` with the
fixed digest is a replication; any other model requires another protocol.

Before code changes, create ignored `results/pic110r3/setup/inspection.json`,
`installed_pic_hashes.json` and `preservation_before.json`. The latter maps
all currently available prior tracked/raw/archive filenames to byte SHA-256.
The original coverage was 1,832; a public clone lacks private archives and must
report its narrower actual coverage. Never invent missing raw artifacts.
Inspect the installed CLI help, SDK signatures, schemas and source rather than
assuming upstream main. Preserve the inspection in the private setup folder.

For a fresh replication, run the `pic110r3_setup inspect` module command below
before fixture preparation. It requires the verified existing wheel under
`results/pic110r2/setup/` and refuses to overwrite an existing setup. The original
campaign performed equivalent inspection before adding R3 code.

```powershell
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_setup inspect
```

## Deterministic preparation and registration

Run from the repository root in PowerShell:

```powershell
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_tasks
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_validation
.venv-pic110/Scripts/python.exe -m pytest -q
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_setup metadata
```

The task builder refuses to overwrite its five deterministic files. In a clone
containing them, verify them against `dataset()`/the committed manifest rather
than rebuilding in place. Task specifications, authoritative sources, delivery
faults, trusted provenance and source schema are separate files. Private gold
is generated by the independent `gold()` implementation into setup, checked
against the hand outcomes in tests, and hashed. Save `schedule()` to setup
before freezing. `configs/experiment.pic-v1.1.0-r3.json` records `settings()`.
Neither the runner nor model prompt loads private gold.

```powershell
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_runner freeze --phase pilot
# Commit the complete protocol, code, tests, fixtures and public freeze locally.
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_runner prepare
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_runner run --panel pilot
```

After a technical-only pilot gate, freeze/commit main without effect-driven
changes. Keep between-panel work inside the campaign's one-hour clock.

```powershell
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_runner freeze --phase main
# Commit the main freeze and technical pilot gate locally before main inference.
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_runner run --panel confirmatory
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_analysis
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_report
```

No retry/resume into an existing panel. All 80 planned task slots remain in
analysis even if inference stops. Warmup is one additional actual generation.
Producer/consumer are logical roles, not independent autonomous agents. Current
validation of an archived producer uses an explicit prior-date query; no past
execution or cryptographic issuer authentication is claimed. C uses actual PIC
SDK objects and CLI integration tests, never an emulated PIC report.

## Offline analysis without the model

With the dependencies installed, this public check uses only sanitized rows:

```powershell
.venv-pic110/Scripts/python.exe -m pic_local_llm_phase_experiment.pic110r3_analysis --check-public
```

It recomputes primary/secondary paired and family estimates without Ollama,
PIC execution or private responses. It checks arithmetic rather than grading
each original response. Exact regrading uses saved raw answers, the frozen
delivery/provenance data and private gold. Analysis refuses to grade any RUNNING
panel. It does not retry inference or alter prior campaigns.

```powershell
.venv-pic110/Scripts/python.exe -m compileall -q src tests
.venv-pic110/Scripts/ruff.exe check .
.venv-pic110/Scripts/ruff.exe format --check .
$checkFiles = (Get-ChildItem src/pic_local_llm_phase_experiment/pic110r3*.py).FullName
& .venv-pic110/Scripts/mypy.exe --ignore-missing-imports $checkFiles
.venv-pic110/Scripts/python.exe -m pytest -q
.venv-pic110/Scripts/python.exe scripts/public_safety_audit.py
```

Raw source references, exact prompts/responses, SDK/CLI outputs and full local
inspection remain under ignored `results/pic110r3/`. Public files expose only
synthetic fixtures, sanitized metrics, code, protocols and identities. Runtime
acceptance, native predicate settlement, envelope discharge and packet usability
retain their distinct finite scopes. They do not certify real-world truth or
overall runtime settlement. A new result is independent of R2 and is not pooled.
